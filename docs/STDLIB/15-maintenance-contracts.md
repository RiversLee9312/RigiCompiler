## 9. 兼容性与维护

- API 默认行为、格式映射、错误和所有权变更时，同步更新本文及相应规范。
- JSON 类型标识与值映射影响已保存数据，首次发布前保留固定兼容样例。
- 不为文件流或 JSON 重新定义 String、shared、async 或 Serializable。
- 性能数字、测试计数和阶段完成记录留在运行结果及 git 历史，不进入本文。
- 以后讨论 protobuf 时独立确定 schema、字段编号、兼容演进和 Serializer 衔接；不宣称 JSON 映射可以直接套用。

## 10. 施工前契约清单

这里列出影响相邻模块或持久化兼容性的已定裁决与实施依赖；各项指向正文，不要求一次决定全部辅助方法拼写。

D1–D8 的公共行为均已确定，首版这批待定项目已收口；具体辅助声明、平台原语与编译器配套工作属于实施依赖。进程环境和其他系统库留待首版之后，不因后续范围未设计而阻塞当前契约。

### D1：流协议与所有权

流的公共行为已定稿至 §4.4 与 §4.5：普通可挂起读写、精确读取、`ISeekableStream`、`StreamWrapperOwnership`、Span 直接字节结果、AutoBuffer 的可定位流视图、`pipe`、预读、故障与关闭状态、单异常展开、非并发契约、文本/标准流和文件入口。
`flush()` 成功返回要求写入真正完成，文件目标包括系统持久化刷新；普通调用不自动另建协程。首版形成可编译的抽象类、接口、枚举及内存/标准流/文件流实现，并验证与既有资源和调度规则一致；不重新开放这些行为选择。
整体文本便利读写由 TextReader/TextWriter 面向通用流提供，整体字节操作沿用 InputStream/OutputStream，不迁入 FS 路径入口，也不改变默认借用、显式刷新或关闭责任。文件专用 getLength/setLength 按 §4.5 实施，ISeekableStream 仍只有 seek/getPosition。

### D2：文本索引与转换

公共行为已定稿至 §4.3：32 位 Unicode 标量 char、UTF-8 字节位置、显式标量访问、严格切片边界、查找/分割/替换/裁剪/拼接、StringBuilder、八种整数及 float/double 的 parse/tryParse 静态扩展方法、由 IntegerRadix 显式选择且默认十进制的整数解析、浮点与失败规则；bool 不提供解析 API。整数按选定进制读取有效数字前缀，不按任何文本前缀自动选择进制；默认读 `0xFF` 得到 0。仅显式 Hexadecimal 模式要求 `0x` / `0X`，其他模式使用无前缀数字，`0b` / `0o` 中的 b/o 是数字前缀 0 之后的停止位置。

首版提供 toLower/toUpper，使用固定 Unicode 17.0.0 的无条件完整大小写映射，支持一对多映射；不支持上下文或地区相关规则，不内置 Case Folding。结果与操作系统、系统语言及进程 locale 无关，本地化由未来外部国际化库承担。

实现时同步 char 的字面量、转换、VM/native、Span 布局及语言/BIL/运行时规范，统一字符串的标量字典序，并补齐 Unicode 数据和公共文本 API；这些是已确定契约的实施依赖。文本流和 JSON 的字符语义统一引用 §4.3.1，既有 JSON 语法和值域不随通用解析器扩展而放宽。

### D3：SB 公共访问与 Serializer 签名

公共行为已定稿至 §4.6：`Any?` 动态根、两层 Serializer 签名、真实 null、Parcel 合法业务字段与独立元数据、所有 Map 的内部条目序列、无值类型转换且字段集合完全匹配的 `fromParcel`。

实现时补齐最小动态访问和通用字段类型反射，同步对象编解码合成器及序列化/类型系统规范；不得保留旧的默认宽松恢复，也不得仅修改 JSON 的检查而遗漏消息、深复制或图模式。Serializer 基类不提供编码配置或 `loopedRefEnabled`。这些属于已确定契约的实施依赖，不再作为未决设计选择。

### D4：JSON 与 SB 映射

公共行为已定稿至 §4.7：完整规范类型名及多态、`readAs` 按目标反射信息解析、默认保留类型信息、`keepTypeInfo=false` 的普通 JSON 表示、数字与字符规则、Map/枚举映射、重复键及字段检查、循环拒绝、编码、格式、限制和错误传播。

保留类型信息时所有 Map 的 `content` 都是 key/value 条目数组；关闭类型信息时仅 String 键 Map 可输出普通 JSON 对象，非 String 键报错。无载荷枚举输出 case 名字符串，带载荷枚举输出普通 `case` 成员和载荷字段。JsonSerializer 独立提供编码配置，默认 UTF-8；基类无此 API。

实现时以正文的两种格式示例为兼容依据，补齐反射及配置 API 的具体声明和可编译调用样例，不重新开放上述行为选择。

### D5：文件系统

公共行为已定稿至 §4.5：不可变 Path、平台路径规则与显式词法整理、相对路径基准、名称编码限制、信息与链接查询、显式 IDisposable 目录 reader、整体目录列表、创建/删除、文件打开模式与长度能力、复制/移动、临时资源、错误分类及值记录序列化。

整体文本读写归 TextReader/TextWriter 对通用流的能力，字节读写归 InputStream/OutputStream；FS 提供文件流及路径/条目操作，不提供按路径整体读写内容的便利入口。NoReplace 和 CreateNew 使用系统保证，移动不跨文件系统退化成复制删除，复制失败允许留下部分目标；清理沿用既有单异常模型。

文件流 flush 的系统持久化语义保持，文件创建/替换及目录项的事务性持久化不隐含在其中。实现时补齐 VM/native 的 FS 原语、请求/句柄保活及错误映射，验证 Windows/Linux 的路径和操作差异；这些是已定契约的实施依赖。§4.10 的入口参数、环境变量、进程当前目录与平台信息继续后置，FS 不以新增这些公共 API 为前提。

### D6：时间值、格式与时钟

公共行为已定稿至 §4.9：纳秒表示与负值规范化、检查溢出的时间运算、UTC 公历范围及数值偏移、DateTime 的严格文本格式，以及 TimeSpan 默认使用的 ISO 8601 日时分秒子集。TimeSpan 不接受年、月或周，零输出 `PT0S`，秒最多九位小数；不使用旧的 `d.hh:mm:ss.fff` 作为默认格式。

单调时钟、Stopwatch、系统睡眠排除及 Timer 的毫秒调度衔接也按正文实施；纳秒表示不承诺宿主时钟具有纳秒分辨率。首版不引入时区数据库、夏令时或本地化格式。实现时同步时间值布局、序列化恢复校验、时钟原语和运行时规范，这些属于已定契约的实施依赖。

### D7：数学 API 与数值边界

公共行为已定稿至 §4.11：八种整数及 float/double 的具体重载、常量、舍入、绝对值、clamp、浮点定义域与特殊值，以及基础运算、sqrt 和超越函数各自的跨后端精度要求。函数使用现有普通调用方式，不引入数值泛型约束或全局舍入模式。

首版提供 local Random 实例，无参构造从系统随机源取得种子，显式 u64 种子及相同调用序列可跨后端和平台复现；算法、种子扩展、范围采样和位消费规则作为兼容契约固定。无全局共享随机状态或密码学随机 API；任意精度数值、复数、矩阵及统计框架由外部库承担。

### D8：集合与算法

公共行为已定稿至 §4.2：List/Map 补充方法、Set/Queue、可空元素与不存在的区分、单次枚举及及早求值的集合算法、稳定排序、比较器和迭代失效规则；延续既有 `==` 判等与 Map 插入顺序，各可变集合不支持并发访问。

Set/Queue 不直接成为 SB 或 Serializable 类型；通过显式 Array/List 转换保存与恢复是固定的标准行为，保留枚举顺序，恢复 Set 时去重，恢复 Queue 时保留重复项。JSON 不隐式转换它们，D3/D4 的类型白名单和 Serializable 字段约束不因此扩大；这不是待后续补齐直接序列化的临时安排。

上述各项复用基础类型与既有异常模型，新增错误类别归所属 NS；模块错误行为以各正文为准，不通过新增聚合异常或更改清理优先级实现。

本清单保留已定契约的正文指向；实现中发现需要改变公共行为时单独讨论，不把辅助 API 的具体化当作重新开放既定选择。
范围扩展另行讨论，不把后续库或 protobuf 当成解决这些契约的隐含前置条件。
