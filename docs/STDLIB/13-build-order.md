## 6. 建议施工顺序

每一步落实已定依赖契约，再完成最小实现和验证，无依赖部分可提前施工：

1. **集合与缓冲区访问**：落实 D8 与 §4.2 已定的集合契约，补齐 Span/String 公共访问能力、集合算法、稳定排序及迭代失效检查。
2. **字节流与内存实现**：落实 D1 与 §4.4 的公共契约，以内存流、AutoBuffer 和短读写/故障替身验证。
3. **文本与编码**：落实 §4.3 与 D2 的 char 标量语义和固定 Unicode 数据，实现字节/标量文本访问、无条件大小写映射、增量 UTF-8、StringBuilder、文本流及多进制整数/浮点解析；整体文本便利读写通过 TextReader/TextWriter 面向通用流提供。
4. **Serializer 公共层**：落实 §4.6 与 D3 的动态 SB 访问、真实 null、元数据隔离及严格 `fromParcel`；同步对象合成器和序列化规范，验证深复制与消息路径。
5. **JSON**：补齐通用字段反射，落实 §4.7 与 D4 的类型引导读取、两种输出形式和编码配置；使用固定映射样例与格式测试实现 JsonSerializer。
6. **时间与数学**：落实 D6/D7 与 §4.9/§4.11 已定的契约，同步纳秒时间值布局及恢复校验，实现时间运算、ISO 文本格式、时钟、基础数学与可复现 Random；无依赖部分可先行。
7. **文件系统**：落实 D5 与 §4.5 已定的 Path、信息查询、目录 reader、创建/删除/复制/移动/临时资源及文件流契约，接入资源/I/O 等待底座与平台错误映射；不依赖新增进程环境 API，不重复实现按路径整体读写内容的便利层。
8. **应用闭环**：使用内存流、标准输入输出和文件流验证配置转换、数据处理、对象状态保存恢复，以及时间和数学的组合使用。

D1–D8 的行为按正文落实，辅助声明及原语签名通过可编译样例具体化；进程环境与其他系统库不列入首版施工。

这里是依赖顺序，不记录实施进度。实际完成情况通过源码、测试和 git 历史确认。
