# 各 NS 的最小能力：core.fs（§4.5）

> 本文件是 [STDLIB.md](../STDLIB.md)（Rigi 标准库 MVP 设计）的章节拆分，§ 编号与原文件一致；总目录与章节索引见该索引文档。

### 4.5 `core.fs`

本模块属于首版。以下公共行为已确定，不以新增 `core.system` 或其他系统库作为前置。

#### 4.5.1 API 分工

- Path 表达路径文本，File/Directory 提供文件和目录操作；通用 `getInfo/tryGetInfo/exists/getRealPath/move/removeLink` 为本 NS 的普通函数。文件系统入口接收 Path，由 String 显式构造，不隐式把普通文本解释为路径。
- 文件打开返回符合 §4.4 的 InputStream/OutputStream 契约的具体文件流。Path 和信息记录不持有系统资源；文件流及目录 reader 才承担对应句柄的关闭责任。
- 整体文本读写归 TextReader/TextWriter 的通用流能力，整体字节读写归 InputStream/OutputStream；本 NS 不另建按路径读取/写入全部内容的便利 API。使用者先打开所需模式的文件流，再组合 §4.4 的公共能力；内存流、标准流和文件流使用相同的文本接口。

#### 4.5.2 Path 与平台路径

- Path 是不可变 struct，保存原始路径文本；构造不访问磁盘，不要求目标存在。拒绝空文本与内嵌 NUL，当前目录显式使用 `.`；不裁剪空白，不展开 `~`、环境变量、通配符或 URI。
- 语法遵循当前平台。Linux 的分隔符为 `/`，反斜杠是普通名称字符；Windows 接受 `/` 与 `\`，支持完整盘符路径及 UNC 路径。首版不提供独立于宿主的平台路径解析模式。异平台的绝对路径文本在当前平台按普通文本解释（如 Linux 上的 `C:\base` 是普通相对名称，不作为绝对 base 被 `toAbsolute` 接受）；跨平台用例须按宿主平台分支断言预期，平台判定经私有原语承担，不在公共 API 暴露平台信息。
- Windows 拒绝 `C:foo`、`\foo` 等依赖隐含盘符状态的形式；调用者使用普通相对路径或完整绝对路径。具体根与名称规则参照 [Windows 路径与命名空间](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)，不将 Windows 的名称限制套用到 Linux。
- 文件操作允许相对路径，以本次调用开始时的进程当前目录为基准；同一次复制、移动等多路径操作固定同一基准，异步内部阶段不重新选择当前目录。内部取得该基准不意味着首版新增当前目录查询/修改 API。
- 不自动做 Unicode 规范化、大小写折叠、分隔符重写或 `..` 消解。Path 的 equals/hash 按保存的文本精确比较，遵循 String 内容语义；大小写不同或拼写不同的路径可以指向同一个文件，Path 相等不承担文件身份判断。
- 提供显式 `normalizeLexically()`，整理分隔符、`.` 与可配对的 `名称/..`，保留相对路径开头无法消解的 `..`，绝对路径不越过根。词法整理不访问磁盘，不保证原路径与结果访问同一对象；文件操作不能先隐式调用它。符号链接会影响 `..` 的实际解析，参见 [Linux 路径解析](https://man7.org/linux/man-pages/man7/path_resolution.7.html)。
- 提供 `join`、`toAbsolute(base)` 和 `relativeTo(base)`。join 后续参数必须是相对路径，绝对参数报错而不丢弃已有前缀；toAbsolute 的 base 必须绝对，以它组合相对路径，已绝对的输入保持自身。relativeTo 只作词法计算，根不同报错，不通过磁盘证明文件间的关系。
- 提供根、父路径、末段名称、扩展名及去扩展名名称。根没有父路径，单段相对路径的父路径为 `.`；扩展名包含点，`.gitignore` 没有扩展名，`a.tar.gz` 的扩展名为 `.gz`。尾部分隔符不产生额外空名称，实际 I/O 前也不静默删除尾部分隔符以放宽原路径的目录要求。
- Windows 首版只接受普通文件路径，拒绝设备命名空间、备用数据流、保留设备名称及会被普通路径规则改写的末尾空格/点名称；不把这些名称静默改成另一个路径。实现正确接入 Unicode 与长路径能力，不在库内统一施加 260 字符限制；仍报告实际系统/文件系统的长度限制，参见 [Windows 长路径说明](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)。内部使用的原生路径前缀不作为用户路径语法扩展。
- 只支持可以无损表达为 Rigi String 的文件名。Linux 非法 UTF-8 名称、Windows 无法解码为 Unicode 标量的名称均报名称编码错误，不替换、不跳过；目录读取遇到此类名称同样失败。首版不增加原始字节路径类型。

#### 4.5.3 信息查询与链接

- `getInfo(path, followLinks: bool = true)` 返回不可变 FileInfo，不存在时抛错；tryGetInfo 仅将不存在转为 null，exists 仅将不存在转为 false，使用相同的链接跟随选项。权限不足、中间分量不是目录、链接循环及其他错误不能伪装成不存在。「中间分量不是目录」的错误类别保留宿主系统差异：Linux 的 stat/lstat 对「文件/其下子路径」报 NotDirectory（ENOTDIR，tryGetInfo/exists 同类别抛出）；Windows 路径属性族对该形态报路径不存在（ERROR_PATH_NOT_FOUND → NotFound，exists 返回 false，逐级创建 createAll 据此对中间文件报 AlreadyExists）。「不能伪装成不存在」约束库层不得折叠宿主已区分的错误种类，不要求 Windows 额外探测中间分量以统一类别；跨平台用例按宿主平台分支断言。
- FileInfo 包含路径、FileKind、普通文件字节长度，以及修改/访问/创建时间。FileKind 成员为 `.File/.Directory/.Link/.Other`；长度为 `i64?`，非普通文件不伪造长度。时间使用 `core.time.TimeStamp?` 保留可取得的亚毫秒部分，缺乏支持的字段为 null，不用元数据变更时间冒充创建时间，不伪造时钟精度。Linux 创建时间须独立取得真实 birth（例如 statx 的返回 `stx_mask` 明确包含 `STATX_BTIME`）；仅请求该字段或看到非零值不足以证明支持，传统 stat 的 ctime/mtime 和宿主库的替代回退也不足以证明真实创建时间。辅助查询失败或与主体 stat/lstat 之间发生路径身份竞态时，不得将辅助结果混入主体记录，创建时间为 null，主体查询成功及其余字段不受影响。
- 信息是一次查询所得的记录，不持有打开句柄、不自动更新，也不承诺各字段组成文件系统的原子快照；重新查询才获得新的记录。不存在与信息范围不可表示是不同失败，不能通过窄化数值或替换为零掩盖范围问题。
- followLinks 为 false 时只查询末段链接本身，断链仍可被识别；它不禁止中间路径经过链接，不构成整条路径的无链接保证。默认文件打开跟随链接，Windows junction 归入 Link；不把所有未知 reparse 类型一律认定为普通文件。
- `getRealPath(path)` 访问文件系统，要求目标存在，解析链接并返回本库可表达的绝对 Path。它与 normalizeLexically 分开；返回路径不是文件身份，同一文件的多个硬链接仍可能得到不同路径。实现防御不变量：`FileSystemInfo.FullName` / `Path.GetFullPath` 仅绝对化路径文本，不等于磁盘真实路径；不仅末段链接，任一中间目录链接都必须解析，且链接前的 `..` 不可预先按字符串折叠。断链可报 NotFound，权限不足与链接循环等错误不能伪装 NotFound；底层变长 UTF-8 输出仍保持容量不足返回正哨兵 2、meta 回所需**字节数**的协议，不因解析路径改变。
- 首版支持识别、访问和删除已有链接；创建符号链接/硬链接及读取链接原始目标文本的入口留待后续。查询成功不保证之后的操作成功，打开、删除、复制和移动仍须自行处理文件系统变化。

#### 4.5.4 目录读取

- `Directory.openReader(path)` 返回 local DirectoryReader，实现 IDisposable，`read(): DirectoryEntry?` 每次取得一个条目，null 表示结束。创建者通过 using/dispose 管理它，结束和失败不免除关闭责任；同实例不支持并发或重入。（名称注：契约原拼写 `Directory.open`——`open` 是语言声明修饰符关键字，本库入口定名 `openReader`，与 §4.5.6 `File.openRead`/`File.openWrite` 的 open 前缀先例一致；§ 编号不变。）
- 不把目录句柄隐含在普通 IEnumerable 中。现有 [for-each 协议](../SYNTAX/06-control-flow.md) 只规定 iterate/moveNext/current，不自动关闭枚举资源；DirectoryReader 的生命周期显式呈现，不能依赖 GC 或循环正常结束来清理句柄。
- 返回顺序不保证排序，不递归，不返回 `.`/`..`，包含隐藏项。DirectoryEntry 保存名称、基于本次打开基准得到的绝对路径，以及可空 FileKind 提示；提示可能不可用或过时，完整信息由 getInfo 另行查询。
- 目录读取不是原子快照，外部修改期间不保证条目集合完整性；到达结束后持续返回 null，重新扫描须重新打开。读取或名称解码失败后进入故障状态，只允许 dispose；关闭/故障后 read 抛 IllegalStateException。关闭失败后仍进入关闭状态，重复 dispose 不重试，清理遵守 §4.4 的单异常和资源保活规则。
- `Directory.list(path, maxEntries?)` 内部打开 reader，收集为独立 List 并关闭；上限超出时报错，不截断返回，中途失败不返回部分列表。未指定上限时仍受容器容量约束，大目录使用 DirectoryReader；list 不因整体读取而新增快照或排序承诺。

#### 4.5.5 创建、权限与删除

- `Directory.create` 只创建末级，父级须存在，目标已存在时报错。`Directory.createAll` 允许已有目录并创建缺失父级；路径中遇到普通文件报错，已有目录链接按正常路径规则解析。中途失败保留已创建的目录，不自动回滚。
- 普通创建使用宿主权限规则：Linux 文件以 0666、目录以 0777 为基础并受 umask 等系统规则影响，Windows 使用正常继承的安全描述符。首版不新增 chmod、ACL、所有者或可执行位管理，也不以统一伪权限替代系统权限。
- `File.delete` 删除文件或链接条目，包括指向目录的链接；删除链接本身，不删除链接目标。`Directory.delete` 只删除真实空目录，不跟随末段链接删除其目标。`removeLink` 专门删除末段链接，非链接时报类型错误。
- 删除目标不存在时默认报错。File/Directory 的 `deleteIfExists` 返回是否实际删除，只把不存在转为 false，不吞掉权限、非空目录或其他失败；对断链的删除仍按链接条目存在处理。
- 首版不提供递归删除、回收站或自动移除只读属性再重试。删除语义不因平台对目录链接使用不同系统调用而变成递归操作。Windows 删除目录 junction/目录符号链接的**链接条目**须选用非递归 `RemoveDirectoryW`（非空目标仍留存），文件/文件符号链接选用 `DeleteFileW`；仅靠 `DeleteFileW` 不能删除目录 junction。调用前的目录属性与明确的 reparse tag（mount point/symlink）判别仅为选择系统调用，不把未知标签一律视作链接，也不能用先 `exists` 再删除模拟原子性；实际成败与错误由最终系统调用确定。`Directory.delete` 则须先拒绝末段链接并报 NotDirectory，不能因 `RemoveDirectoryW` 本身可删除 junction 就直接放行。

#### 4.5.6 文件打开、定位与持久化

- `File.openRead(path)` 只读打开已有文件；`File.openWrite(path, mode)` 必须显式传入 FileWriteMode：`.OpenExisting/.CreateNew/.CreateOrTruncate/.OpenOrCreate/.Append`。分别表示只写已有文件不截断、仅创建新文件、创建或截断、打开或创建不截断、追加；不自动创建父目录。CreateNew 用系统仅创建机制保证已有条目不被覆盖，不能先查询再用覆盖模式打开。
- 首版分别返回输入流或输出流，不提供同时读写的双向文件流。文件流只接受普通文件（末段链接跟随到普通文件可接受）；真实目录报 IsDirectory，FIFO、设备、socket 等非普通文件报 WrongType，不允许因等待 FIFO 另一端在打开调用中同步阻塞 Compute Worker。应以受控非阻塞打开并按已打开句柄判型；Linux 对无 fd 的 ENXIO（FIFO 无读者或 pathname socket）可仅在失败路径以 O_PATH 另取句柄并 fstat 分类，若补查失败保留原始错误，不能先 stat 路径再打开代替句柄校验；确认普通文件后恢复后续 I/O 的既有状态。非追加模式初始位置为 0，除明确选择截断外保留已有内容；追加模式不存在则创建，并通过系统追加机制使每次写入始终到达当时末尾，不能只在打开时定位一次末尾。
- 只读文件流和非追加文件输出流提供 ISeekableStream 能力。追加输出流不提供任意写入定位或 setLength，不承诺跨进程一次大 write 或一整行的原子性；接口能力由具体返回类型体现，不给通用 OutputStream 或 ISeekableStream 增加文件专用成员。
- 具体文件流提供 `getLength(): i64` 查询当前文件长度；可定位文件输出流另提供 `setLength(length: i64)`。负长度或不可表示长度报范围错误；缩短截断、增长部分读取为零，成功后游标保持不变，即使游标已在新末尾之后。该操作不承诺预先分配全部物理空间，也不隐式替代 flush。
- 增长及末尾之后写入的补零是 Rigi 文件流契约，实现不能直接假定所有宿主截断/扩展函数均保证新区域为零。例如 [Windows SetEndOfFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setendoffile) 不定义扩展区域的内容，须由实现补齐零填充及游标保持；失败仍按 §4.4 保留已发生的副作用并进入故障状态。
- 文件输入流的 EOF 表示本次读取时已无数据，不永久关闭流或缓存 EOF；之后再次读取可以看到新增内容。读到当前 EOF 返回 0，不变为持续等待的文件跟随操作；此行为与目录 reader 的固定结束状态不同。
- 默认允许其他进程读写，以及平台支持的重命名或删除；不隐式提供独占锁或内容快照。文件长度和内容可以变化，已打开流按所持句柄操作，不因路径条目改变而自动重新打开其他文件；首版不提供文件锁 API。
- 文件流 `flush()` 等待全部写入及系统持久化刷新成功。Windows 对应 `FlushFileBuffers`，Linux 对应 `fsync` 或满足相同契约的原语；底层等待不得阻塞 Compute Worker，不能把仅有库缓冲提交或系统缓存写入当作完成。平台依据见 [Windows 文件刷新文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers) 与 [Linux 文件同步文档](https://man7.org/linux/man-pages/man2/fsync.2.html)。
- 文件内容的持久化刷新不自动构成文件替换事务，也不自动刷新目录项；普通 move/rename 不承诺跨平台原子提交或断电后的命名空间恢复。首版不提供原子文件替换助手或目录项持久化事务。

#### 4.5.7 复制与移动

- `File.copy(source, destination, mode)` 复制普通文件内容，源链接跟随到文件；源为真实目录报 IsDirectory。FileCopyMode 提供 `.CreateNew/.Overwrite`，默认 CreateNew；前者只创建新目标，已有条目包括断链时报已存在，后者打开或创建目标，已有文件写入前截断。两者均不自动创建父目录。Linux 只读打开目录可能成功，文件面须按已打开句柄判目录，不能靠先查路径代替。
- Overwrite 跟随目标链接并写入其目标文件，不替换链接条目。截断前按实际打开的源/目标系统文件身份拒绝自复制，包括经不同路径或硬链接访问同一个文件；不能仅比较路径文本，也不能只先查名称再打开截断。其余硬链接观察到的是同一个目标文件的内容修改。
- 身份比较的防御不变量：只有在身份查询成功且确认两侧不同之后才允许截断。宿主身份原语不可用、入口缺失或查询失败时必须报错（Unsupported/IO），不得把失败当作「不同文件」继续复制截断；身份读取的接收缓冲必须按宿主原语的完整写入大小准备，不得以部分字段结构充当接收面。
- 复制只承诺内容，不保留 ACL、所有者、创建时间、稀疏布局等元数据；源被其他进程修改时不保证一致快照。实现可组合文件流和 pipe，成功返回前完成目标持久化刷新及所创建流的关闭。
- 复制失败可能留下新建的部分文件，或已被截断/部分改写的旧目标；不自动删除目标或恢复旧内容。关闭与错误传播遵守既有单异常模型，不增加聚合错误。使用原生复制优化时也须保持这一失败契约，不能无条件继承宿主复制函数的自动删除行为。
- `move(source, destination, mode)` 使用系统移动/重命名能力，支持文件、目录和链接条目；源或目标末段为链接时操作条目本身，不跟随它替换目标内容。跨文件系统报错，不自动退化成复制再删除。
- MoveMode 提供 `.NoReplace/.Replace`，默认 NoReplace。NoReplace 遇到任何已有目标条目报错，包括断链；Replace 的覆盖仅限文件/链接条目，不允许目录覆盖或目录合并。移动目录要求目标不存在，目标不存在时两种模式均可正常移动。
- NoReplace 必须由系统操作保证，不能用 exists 加普通覆盖 rename 模拟。目录源的 Replace 同样必须由系统不替换操作保证目标未存在（包括竞态中新建的空目录），不能靠先查询目标再普通 rename；Linux 原语目标已有目录报 IsDirectory、已有文件/链接报 AlreadyExists；其他宿主的具体错误类别保留现有映射。宿主或文件系统不能提供该保证时明确报 Unsupported；实现可采用 [Linux renameat2 的 RENAME_NOREPLACE](https://man7.org/linux/man-pages/man2/rename.2.html) 及 Windows 对应的不替换移动能力，不把底层接口的默认覆盖行为当成本库默认值。
- Windows 目录 junction 虽是末段 Link 条目，属性仍同时带 `DIRECTORY|REPARSE`（tag `MOUNT_POINT`）；普通文件源 Replace 到此类目标须替换 junction 条目，不跟随它改写所指目录或非空目标中的 sentinel。Windows 可对明确的 `MOUNT_POINT` 窄路径用 `SetFileInformationByHandle(FileRenameInfoEx, REPLACE_IF_EXISTS|POSIX_SEMANTICS)` 一次系统重命名；`MoveFileExW(REPLACE_EXISTING)`/`File.Move(overwrite: true)` 在该形态可能以 AccessDenied 拒绝，不得据 DIRECTORY 位把 junction 当真实目录拒绝。NoReplace 仍由系统不替换操作拒绝已有 junction，真实空/非空目录均不得被文件覆盖；宿主不支持所需重命名原语时受控报 Unsupported，不可预删链接再重命名伪造原子性。
- 复制与移动不是跨进程事务，失败不普遍承诺所有路径和内容完全未变。普通查询不能锁定随后访问的对象，也不通过失败后的反向操作伪造自动回滚；上述 Windows tag/源类型预检只作窄路径分流，不是竞态锁，最终成败交系统重命名操作裁决。上述目录源的系统不替换保证针对调用期间源路径仍为所判定真实目录的情形；外部并发换掉源路径条目可使事先源类型判定失效，不承诺对这种源换型提供跨进程事务隔离。

#### 4.5.8 临时文件与目录

- `File.createTemporary(directory, prefix)` 必须显式接收所在目录，原子创建新文件并返回路径与已打开输出流；不先仅生成名称再让调用者另行打开。已有同名项不能被覆盖，名称冲突时可重新选名并重新尝试原子创建。
- `Directory.createTemporary(directory, prefix)` 对应地创建新目录并返回路径。prefix 只作为名称前缀，不允许包含路径分隔符、NUL 或形成当前平台不支持的名称；最终名称仍遵守 Path 规则。
- 调用者负责关闭返回的流以及删除临时文件/目录；关闭不自动删除，不因名称含临时含义而由 GC 清理。首版不新增系统临时目录查询或环境变量访问 API。

#### 4.5.9 错误、序列化与实施边界

- 文件系统失败使用 `core.fs.FileSystemException : core.IOException`，携带 FileSystemErrorKind、操作名称、相关路径，以及可取得的原生错误码；双路径操作保留两条路径。错误种类区分 InvalidPath、InvalidNameEncoding、NotFound、AlreadyExists、PermissionDenied、NotDirectory、IsDirectory、WrongType、DirectoryNotEmpty、ReadOnlyFileSystem、NoSpace、CrossDevice、TooManyLinks、PathTooLong、SharingViolation、Unsupported 和 Other，不靠解析错误消息判断类别。
- Path 形式与名称错误不伪装成不存在；文件打开的非普通文件使用统一自定义归一码 1002 → WrongType（真实目录仍 IsDirectory，不将 FIFO 伪装 Unsupported）。数值范围和已关闭/故障对象仍沿用 OutOfBoundException/IllegalStateException。tryGetInfo、exists、deleteIfExists 只处理各自明确允许的不存在，不吞掉其他错误；系统差异保留原生诊断信息，每次按既有模型传播一个异常。
- Path、FileInfo、DirectoryEntry 可按普通 Serializable 值保存，表示路径文本或当时的信息记录，不代表资源句柄或跨机器可用的文件身份。Path 恢复遵守当前平台的文本规则，恢复信息记录不查询磁盘、不自动刷新；文件流与 DirectoryReader 不提供序列化。
- 文件时间使用 §4.9 的 TimeStamp，底层句柄生命周期复用 core.native。OS 操作通过私有 native 原语与 VM hook 接入；等待挂起当前协程，正常/失败路径均保活资源至完成后再释放，不能在 Compute Worker 上同步阻塞文件操作。
- 复用现有 libuv 及资源/调度底座时，须按本节适配 [libuv 文件操作](https://docs.libuv.org/en/v1.x/fs.html) 的路径编码、错误、目录句柄与请求清理、复制及重命名行为，不能仅透传宿主默认值。VM/native 分别验证 Windows/Linux 的一致公共契约。
- 首版不加入目录监听、内存映射、文件锁、递归复制/删除、回收站、权限管理或原子文件替换助手；进程环境及其他系统库继续后置。这些范围限制不妨碍使用系统已挂载文件系统或普通 UNC 路径。
