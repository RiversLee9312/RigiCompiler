# 文档定位与 MVP 范围（§1–§2）

> 本文件是 [STDLIB.md](../STDLIB.md)（Rigi 标准库 MVP 设计）的章节拆分，§ 编号与原文件一致；总目录与章节索引见该索引文档。

## 1. 文档定位

本文确定标准库 MVP 的命名空间、职责边界、公共契约和施工依赖，作为后续实现的设计入口。
它不是已实现 API 清单或进度报告。

内容分为三类：

- **已确定**：§2 的范围与分层、各节明确标注的已确定契约，以及现有语言和运行时规范规定的语义。
- **建议基线**：尚未裁决的最小能力与新增 API 行为；仅明确标为建议的类型名、方法名和默认值仍可调整，已确定契约不因尚未实现或发布而重新变为待定。
- **契约清单**：§10 汇总 D1–D8 已确定的公共行为及实施依赖；首版这批设计选择均已定稿，不把尚未完成的实现列为待定设计。

现有行为以源码和对应规范为准：

- [语言语法索引](../SYNTAX.md)，尤其是 [类型系统](../SYNTAX/02-type-system.md)、[函数](../SYNTAX/03-functions.md) 和 [序列化](../SYNTAX/13-serialization.md)。
- [协程与调度](../RUNTIME/06-coroutines.md)、[资源管理与 native 互操作](../RUNTIME/08-resources-native.md)、[消息传递](../RUNTIME/09-messaging.md)。
- [架构指南](../agent_guide/architecture.md) 与 [开发验证约定](../agent_guide/development.md)。

新能力实现时同步补充相应 API/运行时规范。不得把本文规划的 API 当成已经存在，也不得通过库重构悄悄改变语言语义。

## 2. 已确定的 MVP 范围

### 2.1 目标

首版聚焦跨平台的文本、集合、流、文件系统、序列化、时间和数学能力，并衔接既有协程与消息设施。通过内存流、标准输入输出及文件流完成数据处理、JSON 对象往返与文件保存恢复；进程环境和其他系统库扩展留待后续。

### 2.2 命名空间

- `core`：语言基础协议、基础异常和现有公共基础类型。
- `core.collections`：集合、迭代协议与集合算法。
- `core.text`：字符串操作、文本构造、编码和基础数值解析。
- `core.io`：字节流、内存流、缓冲流、文本流适配和控制台。
- `core.fs`：路径、文件、目录、文件信息和文件流实现。
- `core.serialization`：格式无关的公共序列化基建，包括 `Serializer` 抽象基类、`Parcel`、现有修饰器及对象转换入口。
- `core.serialization.json`：`JsonSerializer` 和 JSON 专用的配置、解析与诊断。
- `core.coroutine`：现有协程、Task、Executor、Alarm、Mutex 等能力。
- `core.messaging`：现有 Reader、Receiver、Messenger 等消息能力。
- `core.time`：时间值、时间运算、时钟和基础时间文本转换。
- `core.math`：基础数值函数、常量与通用伪随机数。
- `core.native`：现有原生资源句柄与搬运票据等底层互操作设施。

本次划分不要求迁移既有公开类型。例如 `AtomicStruct`、`AtomicArray`、`AtomicList`、`AtomicMap` 和基础异常继续遵循现有位置，不为目录整齐而制造破坏性迁移。

`core.fs` 属于首版，路径、文件/目录操作和文件流按 §4.5 与 D5 的已定契约实施。`core.system`（命令行参数、环境变量、当前目录及平台信息）留待后续，§4.10 保留规划。

### 2.3 不做的内容

- 进程环境和其他系统库扩展留待后续：首版不新增参数访问、环境变量、进程当前目录查询/修改或平台信息 API。已有入口语法与运行时能力保持；`core.fs` 与 `core.io` 的标准流仍在首版范围内。
- MVP 不提供网络库、HTTP、TLS 或 crypto/密码学 API。
- 正则、压缩、数据库支持放在后续，不作为当前 MVP 的实现依赖。
- 不开发 Rigi 私有二进制序列化格式，也不规划 `core.serialization.binary`。
- 后续只考虑另行引入 protobuf 支持；protobuf 不属于本次任务，不预先实现 schema、代码生成或适配器。

标准库使用 §4.3 的统一 Unicode 文本规则，不内置地区定制或本地化能力；本地化需求由未来引入的外部国际化库承担。
子进程管理随进程环境留待后续，首版不引入时区数据库。通用伪随机数属于首版；任意精度数值、复数、矩阵和统计框架不属于本文标准库范围，相关专业能力交由外部库提供。

基础 `hash()` 和集合判等是现有语言能力，不属于密码学库，不能据此承诺加密安全。
